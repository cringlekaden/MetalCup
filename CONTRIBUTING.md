# Contributing

Build the framework and run the relevant test target before opening a pull request. Keep changes focused, preserve engine/editor separation, avoid serialized-format changes unless explicitly reviewed, and add/update documentation for observable behavior. Do not commit Derived Data, caches, user state, generated output, or third-party files without their required notices.

Use an issue template for bugs or proposals. Documentation changes should include link verification and an updated “last verified” line where appropriate.
